# 条码基线卡（MobileNetV3-Large @ 128）

> 第一份**可信**基线。三个 seed 全部在 BN 动量修复（`1e4d870` 之前那次
> `5dfb1fe`）之后产出，评估链路有效。修复前的历史数字（val 99.59% /
> test 97.45%）是在错误的 BN 动量下跑的，轨迹不可比，已作废。

## 1. 配置

| 项 | 值 |
|---|---|
| 配置名 | `barcode_mobilenet_128` |
| 模型 | MobileNetV3-Large（torchvision），**从零训练、无预训练权重** |
| 参数量 | 4,204,306（2 类、单通道） |
| 输入 | 灰度单通道 128×128 |
| BN | 46 层，动量 0.1（见 `docs/BN统计量排查.md`），eps 0.001 |
| 损失 | CrossEntropyLoss（无 label smoothing、无类权重） |
| 优化器 | Adam，lr = 1e-3（固定，无调度） |
| batch size | 32（143 步/轮） |
| 轮数 | 10，按**验证损失最小**选最佳 epoch |
| 数据增强 | 无 |
| 设备 | CPU |
| 数据 | train 4569 / val 979 / test 979；C128 : EAN13 ≈ 1 : 3.3 |
| 复现命令 | `python src/train.py --config barcode_mobilenet_128 --device cpu --num_epochs 10 --num_workers 0 --seed <0/1/2>` |

> 为什么用 CPU：同一配置下 DML 约慢 3 倍（17 min vs 8 min）。DML 上已验证
> BN 修复同样有效（1 轮 val 96.73% / test 97.65%），但基线迭代用 CPU。

## 3. 噪声底与最小可分辨效应

三个 seed 的 test Top-1 标准差只有 **0.11 pt**，95% 置信区间半宽 ±0.26 pt。

| 结论 | 数值 |
|---|---|
| 单 seed 结果不可分辨范围 | ±0.26 pt |
| **最小可分辨效应（约 2 倍半宽）** | **0.5 pt** |
| 换算成测试集样本数 | 0.5 pt ≈ **5 张**（979 张里） |

这意味着：**0.5 pt 以内的"提升"不能声称是改进**；要证明一个方法有效，
至少要带来 5 张以上的净收益，并且用同 seed 配对比较确认。

## 4. 训练曲线特征

| 现象 | 数据 |
|---|---|
| 第 1 轮就到 96.12%（val） | BN 修复后统计量首轮收敛，早期指标可信 |
| 最佳轮集中在 7~9 轮 | 三个 seed 一致 |
| 末段过拟合 | seed 0 的 val loss 从 0.0220（ep7）升到 0.1451（ep10） |
| train/val 差距 | 末轮 train 99.32% vs val 98.16%，约 1.2 pt（远小于第一周 Mini-ImageNet 的 49 pt） |

**推论**：轮数定在 7~8 轮即可，10 轮里最后 2 轮纯属过拟合。
