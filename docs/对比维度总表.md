# 对比维度总表

> 回答一个问题：**这个项目里"对比算法"到底比了哪些维度。**
> 分两层：早期学习阶段的**理论对比**（定性、可推导），和实验阶段的**实测对比**
> （可复现的数字）。文末列出**没覆盖的维度**，避免把结论说过头。

---

## 1. 理论对比维度（学习阶段，`docs/` 下的三份对比表）

### 1.1 卷积算子（`docs/卷积对比.md`）

| 维度 | 说明 |
|---|---|
| 参数量 | 标准 $C_{in}C_{out}K_HK_W$；深度可分离 $C_{in}K_HK_W + C_{out}C_{in}$ |
| 计算量 MACs | 与上式同构，乘输入分辨率 |
| 内存访问 / 算术强度 | 深度可分离卷积算术强度低，会被带宽限制；空洞卷积地址不连续 |
| 并行性 | DW 卷积单任务量过小、并行度低 |
| 部署友好性 | 直接影响实际延迟而非账面 FLOPs |
| 感受野 | $R_i = R_{i-1} + S_{累计} \cdot D \cdot (K-1)$ |

### 1.2 激活函数（`docs/激活函数对比.md`）

| 维度 | 说明 |
|---|---|
| 数学公式 | ReLU / GELU / SiLU |
| 梯度曲线 | 0 点是否跳变、负半轴是否有小负梯度 |
| 计算成本 | 低 / 中 / 高 |
| 死亡神经元 | ReLU 有；GELU 与 SiLU 只在极端负饱和区 |

### 1.3 损失函数（`docs/损失函数对比.md`）

| 维度 | 说明 |
|---|---|
| 数学公式 / 对 logit 的梯度 | CE 是 $p-y$；Focal 额外带 $(1-p_t)^{\gamma-1}$ 调制 |
| 类别不平衡处理 | 是否需要类权重；Focal 对难易样本分别加权 |
| 适配任务 | 互斥分类 / 二分类 / 多标签 |
| 正则化效应 | Label Smoothing 使最优 logit 不被推向无穷，稳定训练 |

### 1.4 模型架构（`docs/模型架构对比.md`）

| 维度 | 说明 |
|---|---|
| 归纳偏置 | 局部性 / 权重共享 / 层次化（CNN 三项都有，ViT 只有局部性 + 全局注意力） |
| 复杂度来源 | 残差连接、深度可分离、SE、NAS 搜索维度 |
| 硬件友好度 | ShuffleNetV2 的四条准则 G1~G4（通道等宽、少分组、低碎片化、少逐元素操作） |
| 与数据的匹配度 | ViT 的可学习偏置占比更高，需要更大数据集 |

## 2. 实测对比维度（实验阶段）

### 2.1 精度（`src/metrics.py`）

| 维度 | 为什么需要 |
|---|---|
| Test Top-1 | 主指标 |
| Test Top-5 | 类别数 ≥5 时有意义；**条码只有 2 类时恒为 100%，无信息量** |
| **per-class Precision / Recall / F1** | 暴露小类失效。条码 128 输入时 C128 召回只有 96.31%，而整体 98.88% 看着很好 |
| **balanced accuracy（macro recall）** | 类别不平衡下的真实水平（97.98% vs 98.88%） |
| macro F1 | 与 balanced 互补，惩罚偏科 |
| 混淆矩阵 | 看出错误往哪个方向倒（C128→EAN13 多，还是反过来多） |
| **错误绝对数** | 979 张测试集上 1 个样本 = 0.10 pt，比百分比更直观 |

### 2.2 复杂度与效率（`src/profiling.py`、`Trainer.latency_test`）

| 维度 | 口径 |
|---|---|
| Params (M) | 全部可训练参数 |
| **MACs (G)** | thop 统计的**乘加次数，不是 FLOPs**（1 MAC ≈ 2 FLOPs） |
| 单张推理延迟 (ms) | 明确定义：**模型已加载、张量已搬到设备之后**，batch=1 跑一次前向；含 kernel 发车空洞，不含读图/预处理/H2D 拷贝 |
| 分设备延迟 | CPU / CUDA / DML 分开测，不混用 |
| 训练耗时 | 每轮秒数与总时长（用于判断"这点精度值不值得多花时间"） |

> **一条实测结论**：batch=1 时 CUDA 延迟**不能**用来比较模型——三个模型 MACs 差
> 19 倍，延迟只差 11%（208~236 个 kernel，每次 launch 约 4.86 µs，固定成本约
> 1.1 ms，MobileNetV3 的 GPU 利用率只有 19%）。有区分度的是 CPU 延迟
> （7.1 ms vs 17.1 ms）和 MACs。

### 2.3 结构维度（条码实验新增）

| 维度 | 用法 |
|---|---|
| 输入分辨率 | 128 / 224 / 128×384；**唯一确定有效的改动** |
| 输入通道数 | 3（原生）vs 1（灰度），首层权重按输入通道求和以保持响应尺度 |
| 累计下采样倍数 | MobileNetV3 原生 32 倍 vs S16 变体 16 倍 |
| 分类头前特征图尺寸 | 4×4（128 输入）/ 7×7（224 输入）/ 14×14（S16） |
| 长宽比保持与否 | `A.Resize` 是各向异性的，单独做了一组对照 |

### 2.4 数据维度（`docs/条码诊断报告.md`）

| 维度 | 用途 |
|---|---|
| 尺寸分布（宽/高/长宽比） | 校验三个 split 是否可比 |
| **尺寸捷径基线** | majority 76.92% / 阈值法 90.40% / 线性 91.42% → 量化"像素网到底贡献了多少"（+7.46 pt） |
| **可解码性分层** | 用 zbar / zxing-cpp 判定能否解出，把错误拆成"图确实太糊"和"模型没学会" |
| 源图分组 | 防泄漏（6073 组，跨 split 0 组） |
| 标签一致性 | `label_name == original_type`、交叉解码复核（可疑率 0.06%） |

### 2.5 统计与鲁棒性（判据本身）

| 维度 | 具体做法 |
|---|---|
| 重复性 | 每个配置 **3 个 seed**，报均值 ± 标准差 |
| **配对比较** | 同 seed 做差，消除 seed 带来的共同噪声 |
| 显著性 | n=3 时配对 t 需 **> 4.303**（p<0.05） |
| **MDE（最小可检测效应）** | 128 输入 std 0.11 → 只能分辨 0.5 pt 以上的差异；小训练集时升到 2.57 pt |
| **划分稳健性** | 反转训练/测试集重跑，验证方向是否成立 |
| 错误集合稳定性 | 逐样本审计，观察错误集合是否随架构漂移 |

## 4. 没有覆盖的维度（别把结论说过头）

| 维度 | 现状 | 影响 |
|---|---|---|
| 显存 / 内存峰值 | **没测** | 只能说"CPU 上跑得动"，不能说"部署内存友好" |
| 吞吐（batch>1、多并发） | **没测**，只有 batch=1 延迟 | 服务端真实吞吐未知；batch=1 延迟已被证明区分度差 |
| 量化 / 剪枝后的精度与延迟 | 没做 | 部署侧的压缩收益未验证 |
| 能耗 | 没做 | — |
| Top-5 | 条码 2 类时退化为 100% | 该维度在条码任务上无效，只在 100 类的基准实验里有效 |
| 跨设备一致性 | DML 只做过等价性抽查 | 三个 seed 的正式对比全部在 CPU 上，DML 未跑完整流程 |

---

## 5. 一句话总结

**理论层**比的是"参数量、计算量、算术强度、并行性、归纳偏置"这些**可推导**的量；
**实验层**比的是"Top-1 / balanced / 小类召回 / MACs / 延迟 / 训练耗时"这些**可复现**
的量，并且额外加了**统计判据**（3 seed、配对 t、MDE）和**数据审查**（泄漏、
标签噪声、尺寸捷径、可解码性）。

条码这一轮真正生效的只有一条判据组合：**同 seed 配对 + 3 seed + MDE**。
没有它，Focal Loss、Label Smoothing、S16 三个"看起来有提升"的方案都会被误采纳。
